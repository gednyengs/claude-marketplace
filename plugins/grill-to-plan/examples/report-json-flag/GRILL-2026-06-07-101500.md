# GRILL — `report --json` flag

## Context
- **Problem:** `report` prints only human-formatted text, so scripts can't consume its output reliably.
- **Goal:** add a `--json` flag that makes `report` emit machine-readable JSON.
- **Consumers/actors:** CI scripts and other programs that shell out to `report`.
- **Non-goals:** changing the human-formatted output; adding other formats (YAML, CSV).
- **Hard constraints:** existing (non-`--json`) behavior must be byte-for-byte unchanged.
- **Testing approach & seams:** CLI invocation seam; golden-output assertions on stdout and exit code.
- **Governing spec / conformance target:** none.
- **Grounding consulted:** the `report` command implementation and its output formatter (code-confirmed).

## Surface Inventory
- **S01** `report` CLI command — code-confirmed — covered by D01, D02
- **S02** `report` stdout format — code-confirmed — covered by D01 (contract C01)
- **S03** `report` exit codes — code-confirmed — considered — no decision — unchanged by this feature
- **S04** `--json` flag (new) — design-intended — covered by D02

## Decisions
### D01 — `--json` emits one JSON object on stdout; human-formatted text is suppressed
- **Rationale:** stdout must be parseable by consumers; mixing human text with JSON breaks them.
- **Rejected alternatives:** send human text to stderr (consumers that capture stderr would still break); newline-delimited JSON (unnecessary — one report is one object).
- **Evidence/source:** common CLI convention.
- **Provenance:** assumed.
- **Confidence:** medium.
- **Implementation impact:** the output formatter gains a JSON branch; the stdout writer switches on the flag.
- **Test impact:** golden-output test asserting stdout parses as exactly one JSON object (per C01) and contains no human text. Seam: CLI invocation.
- **Surfaces:** S01, S02.

### D02 — `--json` is a boolean flag, default off
- **Rationale:** existing scripts never pass it, so default behavior is preserved (hard constraint).
- **Rejected alternatives:** `--format=json|text` (broader than needed now; revisit if more formats arrive).
- **Evidence/source:** the byte-for-byte backward-compat constraint in Context.
- **Provenance:** design-intended.
- **Confidence:** high.
- **Implementation impact:** add the flag to the `report` argument parser.
- **Test impact:** test that `report` without `--json` is byte-for-byte unchanged. Seam: CLI invocation.
- **Surfaces:** S01, S04.

## Formal Contracts
### C01 — `--json` output schema — provenance: design-intended
```json
{
  "items": [
    { "id": "string", "value": 0 }
  ],
  "generated_at": "ISO-8601 timestamp string"
}
```
Exactly one such object is written to stdout. `items` may be empty. No other top-level keys.
