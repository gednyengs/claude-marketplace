# PRD — `report --json` flag

## Problem Statement
Programs that shell out to `report` cannot reliably consume its human-formatted output.

## Solution
A `--json` flag makes `report` emit a single machine-readable JSON object.

## Requirements
R01. As a calling script, I want `report --json` to print one JSON object, so that I can parse results programmatically. (covers S01, S04; see GRILL D01, D02)

R02. Given `--json`, when `report` runs, stdout MUST be a single valid JSON object conforming to GRILL `C01`, with no human-formatted text. (covers S02; see GRILL D01)

R03. Given no `--json`, when `report` runs, output MUST be byte-for-byte identical to the current behavior. (covers S01; see GRILL D02)

## Invariants & Contracts
I01. `report --json` stdout always parses as exactly one JSON object. Schema: see GRILL `C01`.

## Implementation Decisions
Add a boolean `--json` flag to the `report` argument parser; the output formatter gains a JSON branch selected by that flag (GRILL `D01`, `D02`). Component scope: `report` arg parser and output formatter.

## Failure & Recovery
If producing JSON fails internally, `report` exits non-zero with a diagnostic on stderr (exit-code behavior S03 unchanged) and writes nothing to stdout — never partial JSON. Invariant I01 therefore holds on every success path.

## Conformance
None.

## Testing Decisions
Golden-output tests at the CLI invocation seam: (1) `report --json` stdout parses as one object matching `C01`; (2) `report` without `--json` is byte-for-byte unchanged. Test external behavior, not formatter internals. Prior art: the existing CLI golden tests for `report`.

## Assumptions
- GRILL `D01` (suppress human output under `--json`) — provenance `assumed`; `blocking: false`. Most likely item to be revisited.

## Out of Scope
Other output formats; human-output changes; exit-code changes.

## Further Notes
The schema (`C01`) is intentionally minimal; widening it is a separate feature.
